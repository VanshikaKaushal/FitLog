# FitLog

FitLog is a mobile-first, installable workout journal. Log sessions and review your previous sets in a blush-pink interface designed for use at the gym.

## Features

- Start, resume, duplicate, and edit Push, Pull, Legs, or custom workouts.
- Search the exercise library, create custom variations, and copy earlier sets into the current workout.
- Log weight, repetitions, duration, assistance, bodyweight, plate breakdowns, and notes.
- Review exercise history and personal records for comparable sets.
- Export a JSON backup and preview a restore before confirming replacement.
- Install FitLog as a web app and keep logging offline after the first online launch.

## Technology

React, TypeScript, Vite, Tailwind CSS, Lucide, and Dexie over IndexedDB. The service worker is generated by vite-plugin-pwa and Workbox. Dancing Script and Nunito are bundled with the app. Vitest and fake-indexeddb cover the data layer.

The supplied branding source is `fitlog-logo.png`. The `public/` directory contains its favicon, standard PWA icons, Apple Touch Icon, and a padded maskable icon.

## Develop locally

Use Node.js 24 and npm.

```sh
npm ci
npm run dev
```

Run the project checks and preview the production service worker locally.

```sh
npm run check
npm test
npm run lint
npm run build
npm run preview
```

Use the localhost URL printed by Vite for offline testing. Production installation requires HTTPS.

## Publish to GitHub

1. Create an empty **Public** repository named `fitlog` on GitHub. Leave the README, license, and Git ignore options unchecked.
2. Review `git status --short` for any files you plan to publish. FitLog backups, dotenv files, export folders, and database dumps are ignored. Keep personal workout exports outside the checkout.
3. From the FitLog directory, stage the source changes and commit them if needed. Then replace `YOUR-USERNAME` with your GitHub username.

   ```sh
   git add .gitignore README.md index.html package.json package-lock.json vite.config.ts fitlog-logo.png public src
   git diff --cached --stat
   git commit -m "Redesign FitLog and prepare PWA deployment"
   git branch -M main
   git remote add origin https://github.com/YOUR-USERNAME/fitlog.git
   git push -u origin main
   ```

   If `origin` already points to your FitLog repository, skip `git remote add origin`.

[GitHub guide to pushing a local repository](https://docs.github.com/en/repositories/creating-and-managing-repositories/adding-locally-hosted-code-to-github)

## Deploy to Cloudflare Pages

1. In Cloudflare, open **Workers & Pages → Create application → Pages → Connect to Git**. Authorize GitHub and select `fitlog`.
2. Set the production branch to `main`, the build command to `npm run build`, and the build output directory to `dist`. Use the repository root. The checked-in `.node-version` pins Node.js.
3. Choose **Save and Deploy**, then open the HTTPS `pages.dev` URL. Subsequent pushes to `main` trigger production builds.

FitLog switches tabs within the root URL. Pages can serve the build as static files.

[Cloudflare Pages build configuration](https://developers.cloudflare.com/pages/configuration/build-configuration/)

## Install on iPhone and use offline

1. Open the production HTTPS URL in Safari.
2. From the share sheet, choose **Add to Home Screen**. If you don’t see it, scroll to **Edit Actions** and add it.
3. Turn on **Open as Web App** if Safari shows that setting, then tap **Add**.
4. Launch FitLog from the new Home Screen icon and let it open online once. This lets the service worker cache the app, icons, and fonts.
5. To try offline mode, close FitLog, turn on Airplane Mode, and reopen it from the Home Screen. Open a saved workout and log a set.

FitLog uses standalone display mode and prompts before applying an available update once active workouts are complete.

[Apple’s iPhone web app installation instructions](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios)

## Privacy and backups

Workout data, custom exercises, and settings live in IndexedDB for the current browser and site origin. FitLog uses a small local recovery journal for pending edits. The project has no server-side workout storage or analytics. Publishing the repository or the Cloudflare Pages site publishes the app itself. Your records are stored in your browser.

Open **Workouts → Data & Backup → Generate backup**, then download the file or use **Share file** on supported devices. The displayed date records when FitLog generated the export. Keep a copy in a place you can access again, such as Files or iCloud Drive.

To restore a JSON backup, choose it under **Restore backup**, review the record counts, and confirm replacement. Export your current data first if you want to keep it. Use a backup when moving to a new device, browser, or URL, and before clearing website data.
